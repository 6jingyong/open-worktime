# 六座城的一周：逐人 CSV 调研演示

入口：运行 `npm start`，打开 `http://127.0.0.1:8000/cities.html`。

每座城市附带 **300 个虚构匿名人物、两个调研日期、600 条原始记录**，六城合计 3,600 条。内置样表和五列模板都可下载后原样导入。这些是原创合成资料，不是历史统计、作品原设定或真实工人调查，也不增加项目的真实品牌/工厂覆盖。

## 从文件到比较

1. 点击城市卡片加载完整 CSV，或选择自己的本地文件。
2. 在左侧点击日期、工作单位和用工标签。数字为其余当前条件下的记录数，默认显示最新日期。手机筛选默认折叠为当前范围摘要，点击“调整”展开。
3. 比较方式选择用工、单位、日期或城市，再设置 B 组，只改变比较维度。标签支持键盘聚焦和 Enter/空格操作。
4. 查看直方分布、精确计数和用工概览；逐条明细每页 25 条，但不显示岗位。岗位不用于筛选、分组、交叉统计或摘要导出，旧岗位链接会清理为单位/用工层级。
5. 下载完整原文件、当前 A 组逐人 CSV、A/B 汇总 CSV、SVG 或离线 HTML 简报。

例如：东京 → 帝国电子厂 → 比较方式“用工”。最新日期下，直接雇佣 132 条、劳务派遣 42 条；每组包含相应用工标签下的全部岗位，日期和工作单位一致。全厂合计 222 条记录，城市仍为 300 人。原始 CSV 保留混合岗位设定，页面不再细分岗位。

页面采用顶部城市/文件工具栏、桌面左侧筛选和右侧图表。用工差异说明通过对话框按需查看，方法、精确计数、明细和用工概览折叠展示。工时参考放在图表下方，仅改变参考占比，不改变分组或直方图计数。

## 基础五列与可选岗位

UTF-8 CSV（可带 BOM），最多 5 MiB、20,000 条非空记录。基础五列保持兼容，可另外增加一列“岗位”，共六列；列序可以调整，不接受其他额外列。内置六城样表均有岗位；`docs/examples/survey-template.csv` 保留五列格式。

```csv
人物序号,调研时间,公司,雇佣形式,工作时长,岗位
001,2026-10-01,示例电子厂,直接雇佣,44,产品设计师
002,2026-10-01,示例电子厂,直接雇佣,48,流水线工人
003,2026-10-01,示例电子厂,劳务派遣,50,流水线工人
004,2026-10-01,示例电子厂,驻场售后,46,现场工程师
005,2026-10-01,示例电子厂,劳务外包,42,保安
```

| 字段 | 含义与约束 |
| --- | --- |
| 人物序号 | 匿名编号；1–64 位字母、数字、点、下划线或连字符。按文本读取并保留前导零；不要填姓名。 |
| 调研时间 | `YYYY-MM-DD`，古代样表可用 `前200-06-01`。日期会校验。 |
| 公司 | **实际工作单位或服务现场**，不必是签约雇主。外包保安和供应商工程师在帝国电子厂工作时均填帝国电子厂。1–120 字，不含换行/控制字符；逗号和双引号按标准 CSV 转义。 |
| 雇佣形式 | 保留原五列字段名，界面称“用工标签”。接受自雇、直接雇佣、劳务派遣、劳务外包、驻场售后、其他/不确定。 |
| 工作时长 | **每周小时数**，0–168，可含小数。拒绝空白、负数、区间或带单位的文字；不猜测单位或补值。 |
| 岗位（可选） | 工作内容，最多 80 字，未知可留空。同一岗位可以存在多种用工关系。 |

英文表头为 `respondent_id,survey_date,organization,employment_type,weekly_hours`，可另加 `occupation` 或 `job_role`。另接受“匿名编号”“调研日期”“单位”“公司/单位”“周工时”“工作岗位”。英文雇佣值依次为 `self_employed`、`direct_contract`、`labor_dispatch`、`labor_outsource`、`onsite_service`、`other_unknown`。

岗位列可保留在原始 CSV，但页面、明细表和统计结果不显示岗位值，也不按岗位统计。旧链接中的 `occupation`、`compareOccupation` 和岗位比较模式会被丢弃，避免留下不可见的岗位筛选。汇总 CSV、SVG 元数据和简报不携带岗位条件；原始及筛选后逐人 CSV 仍保留可选第六列。这个展示边界不等同于对原始文件进行匿名化。

一行代表一个人物在一个日期的一条记录。同一编号允许跨日期重访；同人同日重复行会拒绝整个文件，即使单位或岗位不同。提示保留原文件行号，原先载入的数据继续可用。空行忽略，缺失值不补零。

默认只显示最新日期。选择全部日期时按记录汇总，同时单列去重人数：内置样表为 600 条记录、300 人，不能当作 600 个独立人物。

## 用工标签如何对照

这些是产品中的描述标签，不是各国共用的法律分类，也不构成法律关系认定。“公司”列不能单独回答谁签合同、谁发工资；当前模型没有完整记录合同期限或服务商名称。

| 标签 | 本演示采用的关系含义 |
| --- | --- |
| 自雇 | 自己经营/接单并安排工作；不把所有农民或个体户自动归入此组 |
| 直接雇佣 | 当前工作单位直接雇佣和安排工作；不自动等于长期合同或正式编制 |
| 劳务派遣 | 机构雇佣，接收单位安排具体工作，雇佣方与工作单位分开 |
| 劳务外包 | 工作单位委托服务，由承包商组织管理团队，例如厂区安保、保洁 |
| 驻场售后 | 供应商/设备商工程师在客户现场维护；这是服务场景，可能与外包关系重叠 |
| 其他/不确定 | 信息不足，不根据岗位或公司名称推断关系 |

当前每行只记录一个标签；样表中的设备商驻场优先记为“驻场售后”，不重复记入外包。实际调研应进一步区分签约雇主、现场管理和服务场景，不能将这些互斥展示标签视为互不重叠的法律制度。

跨语境说明参考日本厚生劳动省的[派遣与请负区别](https://jsite.mhlw.go.jp/ibaraki-roudoukyoku/yokuaru_goshitsumon/jigyounushi/jigyounushi_e/qa_jhaken_ukeoi_chigai.html)：接收单位指挥与承包商管理有区别。东京仍保留1978年氛围，但派遣标签为后世分类的架空映射；厚生劳动省[制度背景资料](https://www.mhlw.go.jp/www2/english/outline/02-5.htm)记载派遣法于1986年7月施行。因此样表不是1978年制度复原，日语“派遣”“请负”与中文标签也不构成法律等同。这些资料只支撑概念与年代边界，不是虚构人数或工时的来源。

## 六个世界与工作现场

| 城市 | 题材/样表日期 | 混合工作现场 |
| --- | --- | --- |
| 亚历山大里亚 | 希腊化氛围；前200年两轮 | 纸草工坊：造纸、抄写、搬运、守门、器具修理 |
| 杭州 | 《大明王朝1566》氛围；1566年两轮 | 江南制造局：织工、机修、账房、护院、货运 |
| 伦敦 | 工业革命氛围；1840年两轮 | 河岸纺织厂：纺织、机修、事务、门卫、清洁 |
| 东京 | 昭和后期氛围；1978年两轮 | 帝国电子厂：设计、流水线、现场工程、安保、保洁、仓储 |
| 废铁城 | 《铳梦》氛围；2530年两轮 | 地面零件工坊：装配、机修、协调、搬运、警卫、义体维修 |
| 母体 | 《黑客帝国》／缸中之脑；1999年两轮 | 模拟办公室：软件、文书、IT 工程、保洁、安保 |

六城各有至少一个包含四种用工标签的工作现场；同一岗位可以有直接/派遣或直接/驻场等关系。机构名、人物、日期、岗位分配、人数与工时均为新编架空资料，现代分类不代表古代制度或作品原设定。

前五城按假想七天周期内实际劳动的现代小时数计，东京不含通勤。母体只计算模拟意识体验到的劳动时间；168 小时舱体接入设定单列，不进入工时或分母。跨城比较要求来源性质与口径相同，单位选“全部”，并显示各自日期。本地导入不与虚构城市混算。

## 生成与分档

- 原始记录为 `data/surveys/*.synthetic.csv`，清单 `data/survey-manifest.json`。版本 `fictional-surveys-v1`，修订 `mixed-workplaces-v2`。
- 重建：`node scripts/generate-survey-demo.mjs`。按单位 × 岗位 × 用工标签设定群组人数、基准工时和偏移，清单保留所有设定。个体工时采用两项确定性偏移之和、少量延时和群组第二轮变化；变化可正、零或负。不预设某种关系的工时一定更长。
- 个体记录独立生成，没有把旧分档表拆成人物。旧 `city-scenarios.json` 仅作为早期汇总素材和题材背景来源，当前页面不读其中计数。
- 生成器同时更新五列模板及 `docs/examples/fictional-city-brief.html`（杭州默认最新日期简报）。
- 从数值直接分入十档：`<35`、`35–<40`、`40–<45`、`45–<50`、`50–<55`、`55–<60`、`60–<65`、`65–<70`、`70–<75`、`75+`。含下界、不含上界，不先四舍五入。
- 比例分母为各组记录数；阈值占比先合计记录，再计算比例。不平均各岗位或用工组的百分比。空组比例与差值为空，差值单位为百分点；不作因果或显著性解释。

## 本地处理与导出

文件仅在浏览器内存处理，不上传或写入浏览器存储；刷新需重新选择。内置 CSV 通过 GET 加载。清单 SHA-256 用于识别原样导回的内置样表或模板，其他文件标为未核验。格式检查不等于来源、问卷或发布权限核验。

内置视图链接保留筛选；本地文件链接只有 `#source=local`，不携带文件名、人物、单位或筛选，也不传递文件。

内置样表提供“同单位不同用工”和“同单位跨期”一键示例：只选择最新日期确有两组记录、或确有前期记录的单位；不会使用岗位条件。本地导入不出现这些预设。东京的用工示例为帝国电子厂直接雇佣 132 条 / 劳务派遣 42 条；跨期示例为同厂两期各 222 条。

常用导出只显示“下载简报”和“复制视图链接”；SVG、汇总 CSV 与 A 组原始 CSV 收在“其他格式”中。原始 CSV 明确提示可含岗位列。本机链接提示仅供本机使用，线上链接则可恢复内置示例条件。

七份内置 CSV 在 `.gitattributes` 中关闭文本换行转换，保证 Windows、Linux、仓库下载及清单 SHA-256 使用相同的原始字节。

| 下载项 | 内容 |
| --- | --- |
| 完整 CSV | 当前文件的原始字节，包含全部日期与单位 |
| 筛选后的逐人 CSV | A 组记录，五列加可选岗位；可再导入，不添加溯源列 |
| 汇总 CSV | A/B 各组十档计数、分母、独立人数、实际日期/单位/用工筛选、参考工时、口径、数据性质；无岗位字段 |
| SVG | 图表、可见数据性质/口径/样本量及嵌入筛选元数据 |
| HTML 简报 | 内嵌 SVG、计数表、筛选、方法和用工说明，无逐人编号/明细，不依赖外部脚本或样式，可离线查看与打印 |

原始 CSV 不额外存数据性质。内置样表以文件名、DEMO 编号和外部清单标明虚构；修改后导回会按未核验处理。原创虚构记录和模板 CC0 1.0 不覆盖作品等第三方权利，也不覆盖用户导入文件。

## 验证

`npm test` 检查清单哈希、记录/人物数量、五列兼容与六列岗位往返、前导零、重访/重复行、日期/工时、数值分档、岗位条件清理及摘要不含岗位值、空组、母体边界和导出一致性。

浏览器检查覆盖标签与焦点、旧岗位链接清理、明细不显示岗位、工时参考不改变分组、关系说明对话框、五列/六列导入与导出，以及桌面和 390px 紧凑布局。
